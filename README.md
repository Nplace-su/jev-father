# Jev Judger · 从夯到拉

用 Jev 评价基于 Jev 的项目。娱乐法庭，只审项目，不审人。

输入一个公开 GitHub 仓库链接，读取范围内的全部源码、文档和配置，用 Jev 的结构化选择来判断：这次到底是用在刀刃上，还是强行接入？机器人项目加试职责边界。

## 运行

需要 Node.js 20.12+，没有第三方依赖，无需 npm install。

```sh
cp .env.example .env
# 在 .env 中填写 TYPESAFE_API_KEY
npm start
```

打开 <http://localhost:3210>。没有 key 也可以点击「先看一个虚构示例」，但不会对真实项目生成假评价。Key 只在后端读取；修改后重启。GitHub 优先使用 `GITHUB_TOKEN`，否则尝试复用本机 `gh auth login` 登录，仅在内存中读取 token；两者都没有时使用匿名额度。`JEV_MODEL` 默认 `jev-latest`。

## Jev native 的全文 harness

```text
GitHub URL
  → 固定默认分支 commit，列出完整目录
  → 全文读取相关源码 / 文档 / 配置（不限制为 8 个文件）
  → 全文分块，按约 24,000 字符组成批次
  → 每批 Jev：5 个独立 Choice（最多 3 批并发）
      适配度 / Jev 的用途 / 实际实现 / 宣传边界 / 机器人职责
  → 多批时再用 Jev Choice 跨文件汇总（每组最多 8 批，必要时多层汇总）
  → 最后一个 Jev Choice：夯 / 顶级 / 人上人 / NPC / 拉
  → 程序展示概率、档位和对应预写短评
```

最终档位直接采用最后一个 Jev Choice，**没有加权总分、没有聊天模型、没有第六个弃权档**。低置信度的分项判断及其概率仍交给汇总和终审，不再转换为 unknown。分项仍允许标识本批未涉及，避免把“没在某个文件看见”变成“项目没有”；这不阻止终审在五档中选择。置信度低于 0.45 时仅在页面提示摇摆，不删掉判断。此阈值是娱乐产品的提示规则，不是正确率保证。

一个小仓库只需读一批再终审；大仓库增加分批和汇总调用。所有完整文本均送入某个阅读批次。每批附带最多两份 README 的开头各 4000 字作为背景，README 全文也在普通批次中送审。汇总使用各批结构化判断、候选概率和来源文件名，不是把全仓库再次塞进同一个请求；这是轻量娱乐评价，不能等同于完整调用图分析。

机器人问题不强制真机，不因仿真扣分，主要看有没有把现成感知、规划或控制器的能力说成 Jev 的能力。合理集成可以获得好评价，没有消融不能直接推出“没价值”。

## 轻量边界

- 只受理公开 GitHub 仓库首页，暂不支持子目录、指定分支、私有仓库。
- 扫描全目录，读取支持格式的源码、文档、配置和小型实验表格；单文件最多 1 MB。排除依赖目录、构建产物、锁文件、环境配置、符号链接和非支持类型（如图片、权重）。页面列出排除路径和原因、实际已读 / 范围内文件数及失败路径。
- 长文本按完整内容分块，不截掉文件尾部。当前一次最多 1000 个相关文件、合计 4 MB；超出范围或 GitHub 目录被截断时直接报处理错误，不偷偷回退到抽样。部分文件网络读取失败时仍可评价已读部分，同时明确显示缺失。
- 不下载执行仓库，不自动打开其外链，不做查重或全面新颖性检索；不能证明抄袭、真机效果或性能优势。
- 待评材料和评分指令分开；提示模型忽略仓库内指令。提示注入仍是模型局限，不把这个玩具当严肃审计。
- 调用次数随文本量增长，无自动重试。页面实时显示读取与审阅进度，可以展开各阶段的原始请求 / 回答及 token usage，或下载完整 JSON。导出不含 API key；调用失败时报错，不伪造档位。
- 服务只监听本机，拒绝跨站请求，同时只审一个项目；目前没有部署鉴权、数据库或历史记录。

## 验证

```sh
npm test
```

测试覆盖 URL 边界、全文件选择、全文分块无丢失、commit 固定、排除与失败项、低置信度保留、多批多层汇总、并发上限、接口失败及严格五档 Choice。离线测试使用 fixture，不证明真实 Jev 的判断质量；真实连通性需要自己的 API key。

核心文件：`lib/github.mjs` 取证，`lib/rubric.mjs` 题目与短评，`lib/judge.mjs` 分批与汇总接口，`public/` 页面。

官方接口依据（2026-09-23 核对）：[HTTP API](https://docs.typesafe.ai/api)、[Choice](https://docs.typesafe.ai/primitives/choice)、[原子问题与代码组合](https://docs.typesafe.ai/introduction)。
